# DB 전용 참고 사항

프론트엔드와 백엔드를 다른 팀원이 만든다면 이 저장소에서 핵심으로 가져갈 것은 `supabase/` 폴더입니다.

## ZIP 업로드와 핀 좌표

ZIP 업로드는 PNG/JPEG 파일 저장을 자동화합니다. 하지만 임의 이미지에서 정확한 핀 좌표를 자동으로 확정하지는 않습니다.

가능한 운영 방식:

1. 기본 보드/센서 템플릿을 미리 만든다.
2. 같은 slug의 ZIP이 올라오면 기존 핀 좌표를 재사용한다.
3. 새 부품은 최초 1회 캘리브레이션으로 각 핀 중심 `x_px`, `y_px`를 입력한다.
4. 이후 같은 export 규격이면 좌표를 계속 재사용한다.

## 사용자 입력에서 회로도까지

DB만으로 회로도가 자동 완성되지는 않습니다. 자동 완성을 하려면 백엔드가 다음 단계를 수행해야 합니다.

1. 사용자 문장에서 부품과 연결 의도를 추출한다.
2. `circuit_component_assets`에서 부품 slug를 찾는다.
3. `circuit_component_pins.aliases`로 `D13`, `D9`, `TRIG`, `ECHO`, `GND` 같은 핀 표현을 매칭한다.
4. 연결 목록을 만든다.
5. 프론트엔드가 이미지와 핀 좌표를 불러와 선을 그린다.

즉, Supabase는 에셋 라이브러리와 핀 좌표의 정답지 역할을 하고, 회로 생성 판단은 챗봇 백엔드가 맡습니다.

## 브레드보드

LED와 푸쉬버튼은 브레드보드 배치를 전제로 하는 편이 안전합니다. 브레드보드는 이미지뿐 아니라 내부 연결 규칙이 중요합니다.

초기 프로토타입에서는 대표 anchor hole만 입력해도 되지만, 정확한 회로 생성을 하려면 다음 데이터가 필요합니다.

- 전원 레일 좌표
- GND 레일 좌표
- 각 행/열 hole 좌표
- 같은 전기 노드로 연결된 hole 그룹

푸쉬버튼도 네 다리 중 같은 쪽 두 다리가 내부적으로 연결되어 있으므로, 백엔드가 이 규칙을 알고 있어야 합니다.

## STL/GLB 제외

이번 운영 흐름에서는 STL/GLB를 ZIP에 넣지 않습니다. “3D 이미지”는 실제 3D 모델 파일이 아니라 고정 카메라에서 렌더링한 PNG/JPEG입니다.
